# Engineering decisions, and the bugs behind them

Each entry follows the same shape: what went wrong (or could have), how it
was found, what changed, and what it cost. All of them happened on this
project; each links to the commit that fixed it.

The recurring lesson: **a language model is a component that is right most
of the time. Anything that must be right every time, like booking,
cancelling, identity or time words, is enforced in code around it.**

---

## 1. The model booked before the caller confirmed → check-then-book, in code

**What happened.** The prompt said "read the booking back and book only
after the caller says yes". In live runs, gpt-6-luna read the details back
and called `book_appointment` in the same reply, before the caller could
answer. It did this in 3 of 4 runs. A `caller_confirmed: true` argument
didn't help, because the model sets that argument itself.

**Fix.** Booking became two tools:
- `check_booking` validates everything and returns the read-back, but
  books nothing.
- `book_appointment` takes no arguments. It books only what was checked,
  and the tool refuses until the transcript shows the caller has spoken
  since the check.

So the model can't book in the same breath, whatever it believes. Cancel
and reschedule later got the same rule ("confirm by repeating": the first
call returns the read-back, the same call again acts).

**Trade-off.** One more model round-trip per booking. A few hundred ms is
worth it for never booking the wrong slot.
[`1df353d`](https://github.com/Harsh251005/clinic-voice-agent/commit/1df353d) · [`fa10dca`](https://github.com/Harsh251005/clinic-voice-agent/commit/fa10dca)

## 2. ElevenLabs heard nothing on real calls → test the way a call feeds audio

**What happened.** Speech-to-text worked in tests and heard nothing on a
live call. There were two bugs:
1. Without server-side VAD, the plugin finalises a sentence only when the
   stream is flushed, which LiveKit never does mid-call.
2. Language auto-detect saw the greeting's silence first, locked onto the
   wrong language (Cyrillic and Chinese output), and committed empty
   transcripts.

**Fix.**
- `server_vad` is on.
- Hindi is pinned: 6 of 6 real-time runs transcribed Hindi, English and
  Hinglish correctly.
- **The test itself changed:** it now streams audio in real time, with
  room noise first and the stream left open, exactly like a call. The old
  test (instant, silent, stream closed) passed with both bugs present.

**Lesson.** A test that feeds input differently from production proves
nothing about production.
[`27351f8`](https://github.com/Harsh251005/clinic-voice-agent/commit/27351f8) · [`e9399ad`](https://github.com/Harsh251005/clinic-voice-agent/commit/e9399ad)

## 3. The voice changed tone mid-sentence → a sentence splitter that knows "।"

**What happened.** Sarvam's voice sometimes changed pitch and volume
halfway through a Hindi reply. LiveKit's sentence splitter doesn't know the
Hindi full stop "।", so a whole Hindi reply went to Sarvam as one block.
Sarvam re-cut it every 150 characters, wherever that fell, and voiced each
piece as a separate take.

**Fix.** Our own splitter (`providers/sentences.py`). It cuts at । ? ! .
(but not in "Dr." or "5.30"), then at commas, then at spaces, with a
220-character cap. Sarvam's own re-cutting is turned off. A guard test
fails if a plugin upgrade stops using our splitter.
[`0028ef8`](https://github.com/Harsh251005/clinic-voice-agent/commit/0028ef8)

## 4. Times said wrong in Hindi → code writes the words, the model copies them

**What happened.** The slots were right, but the voice said "बारह साढ़े
बजे" (backwards for 12:30), "सत्रह बजे" (17 o'clock, which nobody says),
and once invented "ग्यारह" (eleven), borrowed from an example in the
prompt.

**Fix.** Every time a tool returns carries its Hindi words, generated by
code (`spoken.py`: `12:30 (साढ़े बारह बजे)`). The prompt says to use only
those. 12 of 12 replays were clean afterwards.
[`bf97328`](https://github.com/Harsh251005/clinic-voice-agent/commit/bf97328)

## 5. Free times shown as ranges hid booked slots → list every time

**What happened.** `find_available_slots` returned ranges ("10:00 to
13:30"). One slot inside that range was already booked, and the agent
offered it anyway.

**Fix.** Every free time is listed one by one, under fixed parts of the day
(morning before 12, afternoon 12 to 5, evening from 5), and the prompt
forbids summing them up as a range.
[`88a38aa`](https://github.com/Harsh251005/clinic-voice-agent/commit/88a38aa)

## 6. Romanised Hindi was mispronounced → replies in Devanagari

**What happened.** A wire capture showed replies like "main aapki kya
madad kar sakti hoon" going to the voice engine, which read them with
English spelling rules.

**Fix.** Hindi and Hinglish replies are written in Devanagari, including
the English words mixed in ("अपॉइंटमेंट"). Sarvam's own docs later
confirmed that romanised input "significantly degrades output quality".
[`11a6aa1`](https://github.com/Harsh251005/clinic-voice-agent/commit/11a6aa1)

## 7. "Let me check…" and then silence → promises are kept by code

**What happened.** For about 1 in 5 answers to "can I see the doctor
tomorrow?", the model said "मैं कल के स्लॉट्स चेक कर लेती हूँ" ("I'll
check tomorrow's slots") and called no tool. The reply ended, and the
caller heard nothing.

**Fix.** `keep_promises` watches each finished reply. If it promised to
check, called no tool and didn't end on a question, it gets an immediate
follow-up that is forced to call a booking tool. A forced follow-up is
never forced again, so there are no loops. 8 of 8 real-model runs
answered with times; one of them hit the bug and was rescued.
[`e03ef44`](https://github.com/Harsh251005/clinic-voice-agent/commit/e03ef44)

## 8. Hanging up in silence → the goodbye is an argument of `end_call`

**What happened.** LiveKit's built-in `EndCallTool` asks the model for the
goodbye in a second reply after the tool runs. When that reply was empty,
or the caller's voice interrupted it, the call just ended.

**Fix.** Our own `end_call(goodbye)`. The goodbye is part of the tool call.
It is spoken with interruptions off and played out fully before the room
is deleted, and an empty goodbye gets a stock one. It is also hidden during
the greeting: with tools available there, the model once looked up slots
and offered them before the caller had said a word.
[`cb5c833`](https://github.com/Harsh251005/clinic-voice-agent/commit/cb5c833) · [`aaa17bd`](https://github.com/Harsh251005/clinic-voice-agent/commit/aaa17bd)

## 9. Double booking → the database refuses it, not the code

Two callers can pick the same slot at the same moment. Code that checks
"is it free?" and then inserts would race.

**Decision.** A partial unique index: one booked appointment per (doctor,
start time), with cancelled rows excluded. The second insert fails
atomically. Only that index's violation becomes "just taken, here are other
times"; any other database error still surfaces. Tests prove it on SQLite
and Postgres.

**It shaped a later design.** Visit marks (Arrived, Done, No-show) are
their own column, not a status. Any status other than `booked` would free
the slot while the patient sits in the waiting room.
[`3a24097`](https://github.com/Harsh251005/clinic-voice-agent/commit/3a24097) · [`071c85b`](https://github.com/Harsh251005/clinic-voice-agent/commit/071c85b)

## 10. Multi-tenant access → every row id checked, and a test that attacks it

One dashboard serves many clinics. The URL carries row ids, so a member of
Clinic A could try Clinic B's appointment id (IDOR).

**Decision.**
- Every route that takes an id goes through `repo.in_clinic`.
- A clinic you can't open is a 404, not a 403, so its existence doesn't
  leak.
- A parametrised test (`ATTACKS`) tries every row type through both URLs.
  It fails if the check is removed, which was verified.
- An admin who isn't on a clinic's team can set the clinic up but can't see
  its patients.
[`a29c092`](https://github.com/Harsh251005/clinic-voice-agent/commit/a29c092)

## 11. Privacy by design: text, not audio; logged break-glass

- **No audio is ever stored.** LiveKit's own recording is off
  (`record=False`).
- **Each call is kept as two things.**
  - A **trace**: timings, tool names, error types, how it ended. It holds
    no words, so the operator can always see it.
  - A **transcript**: patient data, in its own table, deleted after 30
    days.
- **The operator can open a transcript only by writing a reason.** It is
  logged, and the clinic sees that support opened it.
- **Patients' call pages report failures as fixed codes only.**
  Unhandled server errors are recorded as the route and the error type,
  never the request, because a request or an error message can carry
  patient data.

## 12. Swappable vendors → one registry per part, tested at boot

Speech-to-text, the model and the voice are each chosen by one line in
`.env` (Sarvam, ElevenLabs, OpenAI), through a `BUILDERS` registry.
- Only `providers/` imports vendor code, and a test enforces the
  boundary.
- Boot builds all three, so an unknown vendor or a missing key is a
  one-line startup error, not a failure on the first call.
- Reasoning models get `reasoning_effort="none"` automatically.
  gpt-6-luna otherwise refused tools with a 400 on every turn.
